Case study · GovTech · e-Governance

Paperless workflow platform

A digital platform that moved a government client's paper-based work online, with live updates on every screen.

Role
Frontend engineer
Built at
Edstem Technologies
Scale
Government
Stack
React · Java · Python

The problem

The client's day-to-day work ran on paper. Documents and records were printed, circulated and filed by hand.

They needed one digital platform that staff could rely on while work was in progress, where downtime or stale data simply isn't acceptable. It also had to be big: many modules, built by several people in parallel.

What I built

Architecture

Micro-frontends

I structured the platform with Module Federation, so each module could be developed, tested and deployed independently inside one shared shell.

Real-time

Live status monitoring

WebSockets push live status to every screen as it changes, with no refreshing and no out-of-date views.

Workflow

Document workflows

Documents are tracked digitally through their stages, replacing paper copies and manual status updates.

Full-stack

Across the stack

Alongside the React frontend I worked with the Java and Python services and the DevOps workflows that ship them.

Outcome

The client's day-to-day work went fully paperless, on a platform running at government scale.
  • Documents and records moved from paper to one platform
  • Modules shipped independently without blocking each other

Tech used

ReactModule FederationMicro-frontendsWebSocketsJavaPythonREST APIsDevOps

Takeaway

"Big app, many teams? Micro-frontends let each part ship on its own schedule without waiting for everyone else."
