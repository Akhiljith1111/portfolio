Case study · GovTech · e-Governance

e-Niyamasabha

A digital legislative management platform that let a State Legislative Assembly run fully paperless sessions.

Role
Frontend engineer
Built at
Edstem Technologies
Scale
State government
Stack
React · Java · Python

01 The problem

Legislative business ran on paper. Bills, attendance and session records were printed, circulated and filed for every sitting.

The Assembly needed one digital platform that members and staff could rely on during live sessions, where downtime or stale data simply isn't acceptable. It also had to be big: many modules, built by several people in parallel.

02 What I built

Architecture

Micro-frontends

I structured the platform with Module Federation, so each module could be developed, tested and deployed independently inside one shared shell.

Real-time

Live session monitoring

WebSockets push live session status and attendance to every screen as it changes, with no refreshing and no out-of-date views.

Workflow

Bill management

Bills are tracked digitally through their stages, replacing paper copies and manual status updates.

Full-stack

Across the stack

Alongside the React frontend I worked with the Java and Python services and the DevOps workflows that ship them.

03 Outcome

Legislative sessions went fully paperless, on a platform running at state-government scale.
  • Bills, attendance and session records moved from paper to one platform
  • Modules shipped independently without blocking each other

04 Tech used

ReactModule FederationMicro-frontendsWebSocketsJavaPythonREST APIsDevOps

05 Takeaway

"Big app, many teams? Micro-frontends let each part ship on its own schedule without waiting for everyone else."
