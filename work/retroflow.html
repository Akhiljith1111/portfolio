Case study · SaaS · Agile tools

RetroFlow

A sprint-retrospective SaaS product. I built every frontend screen and the reusable component library from a blank repo.

Role
Frontend engineer
Built at
Edstem Technologies
Type
SaaS product
Stack
React · Redux · Vite

The problem

Retrospectives usually happen in spreadsheets or generic whiteboards. Feedback gets scattered and action items are forgotten by the next sprint.

RetroFlow needed a focused, pleasant tool that teams would actually want to open every sprint, and a frontend that could keep growing with the product.

What I built

Frontend

Every screen, from scratch

I built all the product screens, from boards and columns to cards and actions, starting from an empty repository.

Design system

Reusable components

A shared component library in Styled Components and Tailwind CSS kept the UI consistent and made new screens fast to build.

Data

State & API integration

Full state management with Redux plus REST API integration, so boards stay in sync as the team adds feedback.

Tooling

Fast developer loop

Vite-powered builds kept the feedback loop near-instant while iterating on the UI.

Outcome

A complete retrospective product UI, built from an empty repo to a working SaaS.
  • Every screen and component built in-house
  • One component library behind the whole product

Tech used

ReactReduxStyled ComponentsTailwind CSSViteREST APIs

Takeaway

"Starting from zero? Build the component library on day one, and screen number twenty ships as fast as screen number two."
